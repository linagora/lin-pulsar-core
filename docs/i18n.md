# 🌐 i18n Singleton and Scoped Composable

This document explains how to use the shared i18n singleton and the `useScopedI18n` composable to manage translations in
your application.

---

## 1. Overview

The i18n singleton provides a **shared instance of `vue-i18n`** across all modules. It ensures that all modules use the
same translation store, avoiding duplication and inconsistencies.

The `useScopedI18n` composable allows you to create a **scoped translation function** bound to a specific namespace,
automatically prefixing all translation keys.

---

## 2. Shared i18n Singleton

### 2.1 Initialization

The shared i18n instance must be initialized **once** by the host application during boot. The languages, the default
locale and the translation files come from the `i18n` entry of the application `config.json` (see
[Application Configuration](./module-lifecycle.md#application-configuration)). The translations of the components of
the `linPulsar` catalog are not shipped by the catalog: they must be provided by these application translation files.

```ts
import { createI18n } from 'vue-i18n';
import { setI18nInstance } from '@linagora/lin-pulsar-core';
import messages from 'public/i18n/messages.json';

const i18n = createI18n({
  legacy: false,
  locale: 'en',
  fallbackLocale: 'fr',
  messages,
});

setI18nInstance(i18n);
```

The instance must be created in Composition API mode (`legacy: false`): the library reads and writes its global
composer (`i18n.global.locale.value`).

> ⚠️ Subsequent calls to `setI18nInstance()` are ignored.
> Accessing the instance via `getI18nInstance()` before initialization will throw an error.

### 2.2 Accessing the Singleton

You can retrieve the shared i18n instance anywhere in your code:

```ts
import { getI18nInstance } from '@linagora/lin-pulsar-core';

const i18n = getI18nInstance();
i18n.global.t('application.title');
```

To switch the active language, use [`changeLocale`](#43-changelocale) rather than writing `i18n.global.locale`.

- `getI18nInstance()` returns the **same instance** everywhere.
- Ensures consistent locale, messages, and formatting across modules.

## 3. Using the `useScopedI18n` Composable

The `useScopedI18n(scope: string)` composable creates a scoped `t` function bound to a **translation namespace**.

### 3.1 Import and Setup

```ts
import { useScopedI18n } from '@linagora/lin-pulsar-core';

const { t, te, tm, translateOrDefault } = useScopedI18n('user.profile');
```

- All translation keys will be automatically prefixed with `user.profile`.
- Example: `t('name')` → `'user.profile.name'`.

### 3.2 Using `t`

The `t` function supports all overloads of Vue I18n's `t`:

1. **Simple translation**

```ts
t('name'); // translates 'user.profile.name'
```

2. **Named interpolation**

```ts
t('greeting', { username: 'Alice' });
// translates 'user.profile.greeting' replacing {username} with 'Alice'
```

3. **Pluralization**

```ts
t('messages', 5);
// translates 'user.profile.messages' using plural rules
```

4. **Advanced options**

```ts
t('greeting', { username: 'Alice' }, { locale: 'fr-FR' });
// named values in the second argument, translation options in the third
```

### 3.3 Using `te` to Check Key Existence

The `te` function allows you to check if a translation key exists in the scoped namespace:

```ts
if (te('greeting')) {
  console.log('Key exists!');
}
```

- Returns `true` if the key exists, otherwise `false`.
- Useful for conditional rendering or fallback logic.

### 3.4 Using `tm` to Retrieve Raw Messages

The `tm` function retrieves the **raw translation message** without formatting:

```ts
const rawMessage = tm('greeting');
console.log(rawMessage); // e.g., "Hello, {username}!"
```

- Returns the raw message, or an empty object `{}` if the key does not exist.
- Useful for logging, dynamic processing, or template generation.

### 3.5 Using `translateOrDefault`

The `translateOrDefault` function provides a **safe fallback** when a key may not exist:

```ts
const message = translateOrDefault('Hello!', 'greeting', { username: 'Alice' });
```

- Returns the translated string if the key exists.
- Returns the provided default value otherwise.
- Accepts the same arguments as `t()` (key, pluralization, named interpolation, options).

## 4. Locale Management

Three helpers manage the active locale, its resolution, and its persistence. They rely on the shared i18n singleton
and on the UI store (`useLinPulsarUiStore`), which must hold the available languages and current locale. The host is
responsible for populating the store during boot (via `setAvailableLanguages` and `setLocale`) **before** these
helpers are called, since `resolveLocale` reads the supported languages from the store.

### 4.1 `resolveLocale`

Resolves the effective locale to apply, without any side effect. Resolution priority: stored user preference, then
locally persisted language (`localStorage`), falling back to the locale held in the UI store when none is supported.

```ts
import { resolveLocale } from '@linagora/lin-pulsar-core';

const locale = resolveLocale();
```

### 4.2 `syncLocale`

Synchronises the persisted state with the given locale. The locale is always written to `localStorage`. The
server-side user preference is updated only when it differs from the currently stored one.

```ts
import { syncLocale } from '@linagora/lin-pulsar-core';

await syncLocale('fr-FR');
```

### 4.3 `changeLocale`

Applies the given locale to the application and persists the choice: updates the active i18n locale, reflects it in
the UI store (`setLocale`), and synchronises the persisted state via `syncLocale`. This is the function to call from
a language switcher.

```ts
import { changeLocale } from '@linagora/lin-pulsar-core';

await changeLocale('fr-FR');
```

## 5. Full Example in a Vue 3 + Quasar Component

```vue
<script setup lang="ts">
import { useScopedI18n } from '@linagora/lin-pulsar-core';

const { t } = useScopedI18n('user.profile');

const welcomeMessage = t('greeting', { username: 'Alice' });
</script>

<template>
  <q-page>
    <h1>{{ welcomeMessage }}</h1>
  </q-page>
</template>
```

- Keys are automatically prefixed with the specified namespace.
- The same component can be reused with different namespaces.

---

## 6. Best Practices

- Always call `setI18nInstance()` **once** during app boot.
- Use descriptive namespaces for different modules or features.
- Keep translation keys organized and avoid deeply nested structures unless necessary.
- Use `useScopedI18n` in components to reduce repetition and ensure correct namespace scoping.

---

## 7. TypeScript Support

The composable preserves type safety with Vue I18n's `ComposerTranslation` type:

```ts
import { useScopedI18n } from '@linagora/lin-pulsar-core';

const { t } = useScopedI18n('user.profile');

const message: string = t('greeting', { username: 'Alice' });
```

- Supports key-only, pluralization, named interpolation, and options overloads.
