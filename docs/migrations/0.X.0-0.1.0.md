# 🧭 Migration guide: `0.0.x` → `0.1.0`

Version `0.1.0` renames the library from `@linagora/linid-im-front-corelib` to `@linagora/lin-pulsar-core`, as part
of the move from LinID to LinOpenFactory and LinPulsar. Apart from names, the only behavior change is a new error log
when a module or zone file fails to load with an HTTP error status (`Failed to load file: … (HTTP …)`).

All consumers (the host application and every remote) must migrate **at the same time**, since the library is shared
as a strict singleton through Module Federation.

---

## 1. Package

Replace the dependency in `package.json`:

```diff
-"@linagora/linid-im-front-corelib": "0.0.109",
+"@linagora/lin-pulsar-core": "0.1.0",
```

Then update every import:

```diff
-import { useLinidZoneStore } from '@linagora/linid-im-front-corelib';
+import { useLinPulsarZoneStore } from '@linagora/lin-pulsar-core';
```

And the `shared` entry of the Module Federation configuration:

```diff
 shared: {
-  '@linagora/linid-im-front-corelib': {
+  '@linagora/lin-pulsar-core': {
     singleton: true,
     strictVersion: true,
   },
 },
```

---

## 2. Exported identifiers

Every exported identifier containing `Linid` / `linid` / `LINID_` is renamed with the same rule:

| Prefix in `0.0.x` | Prefix in `0.1.0` |
| ----------------- | ----------------- |
| `Linid`           | `LinPulsar`       |
| `linid`           | `linPulsar`       |
| `LINID_`          | `LIN_PULSAR_`     |

The Quasar props types follow the same rule (`LinidQBtnProps` → `LinPulsarQBtnProps`, `LinidHtmlAttrs` →
`LinPulsarHtmlAttrs`, ...). All the other renamed identifiers are listed below:

| 0.0.x                              | 0.1.0                                  |
| ---------------------------------- | -------------------------------------- |
| `BaseLinidZoneEntry`               | `BaseLinPulsarZoneEntry`               |
| `ComponentLinidZoneEntry`          | `ComponentLinPulsarZoneEntry`          |
| `FederatedLinidZoneEntry`          | `FederatedLinPulsarZoneEntry`          |
| `LINID_FILTER_NEGATION_PREFIX`     | `LIN_PULSAR_FILTER_NEGATION_PREFIX`    |
| `LINID_FILTER_OR_SEPARATOR`        | `LIN_PULSAR_FILTER_OR_SEPARATOR`       |
| `LinidApiEndpointConfiguration`    | `LinPulsarApiEndpointConfiguration`    |
| `LinidApiErrorResponseBody`        | `LinPulsarApiErrorResponseBody`        |
| `LinidAttributeConfiguration`      | `LinPulsarAttributeConfiguration`      |
| `LinidEntityConfiguration`         | `LinPulsarEntityConfiguration`         |
| `LinidFilter`                      | `LinPulsarFilter`                      |
| `LinidFilterDynamicLabelOptions`   | `LinPulsarFilterDynamicLabelOptions`   |
| `LinidFilterOperator`              | `LinPulsarFilterOperator`              |
| `LinidFilterSet`                   | `LinPulsarFilterSet`                   |
| `LinidFilterSetUserPreference`     | `LinPulsarFilterSetUserPreference`     |
| `LinidFilterType`                  | `LinPulsarFilterType`                  |
| `LinidFilterValue`                 | `LinPulsarFilterValue`                 |
| `LinidModuleFederationInitOptions` | `LinPulsarModuleFederationInitOptions` |
| `LinidModuleFederationPhaseRunner` | `LinPulsarModuleFederationPhaseRunner` |
| `LinidRemoteConfig`                | `LinPulsarRemoteConfig`                |
| `LinidRoute`                       | `LinPulsarRoute`                       |
| `LinidRoutes`                      | `LinPulsarRoutes`                      |
| `LinidUser`                        | `LinPulsarUser`                        |
| `LinidZoneEntry`                   | `LinPulsarZoneEntry`                   |
| `LinidZoneRenderer`                | `LinPulsarZoneRenderer`                |
| `LinidZoneResolvedEntry`           | `LinPulsarZoneResolvedEntry`           |
| `linidModuleFederation`            | `linPulsarModuleFederation`            |
| `useLinidConfigurationStore`       | `useLinPulsarConfigurationStore`       |
| `useLinidFilterUrl`                | `useLinPulsarFilterUrl`                |
| `useLinidUiStore`                  | `useLinPulsarUiStore`                  |
| `useLinidUserPreference`           | `useLinPulsarUserPreference`           |
| `useLinidUserPreferenceStore`      | `useLinPulsarUserPreferenceStore`      |
| `useLinidUserStore`                | `useLinPulsarUserStore`                |
| `useLinidZoneStore`                | `useLinPulsarZoneStore`                |

The rule can be applied to a code base with a single command. Review the result before committing it: it also
renames your own identifiers containing `Linid`, which may not be wanted.

```bash
grep -rlE 'linid-im-front-corelib|Linid|linid|LINID_' src tests \
  | xargs perl -pi -e 's/linid-im-front-corelib/lin-pulsar-core/g; s/LINID_/LIN_PULSAR_/g; s/Linid/LinPulsar/g; s/linid(?=[A-Z])/linPulsar/g'
```

## 3. Pinia store ids

The ids of the Pinia stores are renamed. Code that refers to a store by its id (Pinia plugins, persisted state,
devtools filters) must be updated:

| 0.0.x                      | 0.1.0                          |
| -------------------------- | ------------------------------ |
| `LinidConfigurationStore`  | `LinPulsarConfigurationStore`  |
| `LinidUiStore`             | `LinPulsarUiStore`             |
| `LinidUserStore`           | `LinPulsarUserStore`           |
| `LinidUserPreferenceStore` | `LinPulsarUserPreferenceStore` |
| `linidZoneStore`           | `LinPulsarZoneStore`           |

---

## 4. Log messages

The prefix of the messages logged or thrown by the library changes from `[LinID CoreLib]` (and `[Linid CoreLib]`
for the configuration store) to `[LinPulsar Core]`.
Tests asserting these messages must be updated.

---

## 5. Build output

Only relevant when the build output is referenced directly instead of through the package entry points:

| 0.0.x                  | 0.1.0                         |
| ---------------------- | ----------------------------- |
| `dist/core-lib.es.js`  | `dist/lin-pulsar-core.es.js`  |
| `dist/core-lib.umd.js` | `dist/lin-pulsar-core.umd.js` |
| UMD global `CoreLib`   | UMD global `LinPulsarCore`    |
